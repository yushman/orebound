# scenes

Game scenes.

- `Run.tscn` (Node2D, main scene) holds an instance of `Ship.tscn`, the `Prediction` `Line2D`, the `ReferenceMarker`, 3 `Body.tscn` instances: planet (`index` 0) and 2 moons (`index` 1, 2), and a `CanvasLayer` with a `ui/TuningPanel.tscn` instance (hidden on start, screen-fixed under the `Camera2D`).
- `Ship.tscn` is a `CharacterBody2D` named `Ship` with `Ship.gd`, a `Polygon2D` triangle (nose toward local -Y), a `CollisionShape2D` with a `CircleShape2D` and a child `Camera2D` with `ignore_rotation = true` (north stays up).
- Flight physics is the pure `ShipFlight.step(state, input, t, dt) -> ShipState` (`class_name`, static, no scene dependency, so trajectory prediction can reuse it). It returns a new state, never mutates its arguments, and is deterministic. `ShipParams` are read from `Tuning.ship` on each call, no cache.
- Step order: rotation, thrust or brake, translation, fuel. Rotation: angular acceleration is `turn * turn_accel` (turn in {-1, 0, 1}), or with `has_heading` `clamp(heading_gain * wrapf(target_heading - rot, -PI, PI) - 2·sqrt(heading_gain)·ang_vel, ±turn_accel)` (PD, critically damped, so the nose does not overshoot); then `ang_vel = (ang_vel + ang_acc·dt)·exp(-spin_damping·dt)` (damping always on), `rot = wrapf(rot + ang_vel·dt, -PI, PI)`. Thrust acts along the nose `Vector2.UP.rotated(rot)`. Translation is semi-implicit Euler: `vel += (GravityField.accel(pos, t) + nose·thr)·dt`, then `pos += vel·dt`.
- Boost: `boost` alone gives thrust `thrust_accel·boost_accel_mult` (`thrust` is not required) and only `fuel_boost` grows, by `thr·dt·fuel_per_dv·boost_fuel_mult`; plain `thrust` grows only `fuel_engine` by `thr·dt·fuel_per_dv`; no thrust, no fuel. Fuel is per delta-v, so the boost ratio holds under any acceleration tuning. Fuel only accumulates; there is no tank limit.
- Brake: `ShipInput.brake` (held `ship_brake`) is handled inside `ShipFlight.step`, so prediction stays identical to real flight. The reference is `ShipFlight.reference_body(pos, t) -> int` (returns `GravityField.dominant`, the body with the largest pull; the single extension point for asteroids/carrier, only bodies are references), recomputed each step, not stored in the state. In the reference frame `r_rel = pos - body_pos(ref)`, `v_rel = vel - body_vel(ref)`; tangent sign is the sign of `r_rel.cross(v_rel)` (spawn direction, counter-clockwise, when `|cross| < 1e-6·|r_rel|·|v_rel|`), so a retrograde orbit stays retrograde. `v_target = body_vel(ref) + tangent·circular_speed(ref, pos, t)`; `a_b = (v_target - vel)/dt` clamped to `brake_accel`, independent of the nose, applied as `vel += (g + a_b)·dt` where thrust acts. While brake is held thrust and boost are ignored (no thr, no engine/boost fuel), so fuel is not wasted fighting the engine; rotation still works. Near the target orbit only the residual error is applied. `fuel_brake += |a_b|·dt·fuel_per_dv·brake_fuel_mult`: per dv brake costs slightly more than the main engine. Accepted costs: near a moon the planet's pull also acts, so a moon orbit is not exactly circular and brake keeps correcting; a reference switch makes `v_target` jump, smoothed only by the `brake_accel` clamp.
- `ReferenceMarker` (`ReferenceMarker.gd`, Node2D in `Run.tscn`) moves each physics tick to `body_pos(ShipFlight.reference_body(ship.state.pos, t), t)` and draws a ring there; always visible (the player knows the reference before braking), brighter while `ship.input.brake`.
- `ShipState` (`pos`, `vel`, `rot`, `ang_vel`, `fuel_engine`, `fuel_boost`, `fuel_brake`) and `ShipInput` (`turn`, `has_heading`, `target_heading`, `thrust`, `boost`, `brake`) are `RefCounted` with typed fields and `copy()`; fuel counters live in the state, not on the node.
- `Ship.gd` holds the authoritative `state`. `_ready` calls `respawn()`, which is also connected to `Tuning.preset_applied` (a preset load puts the ship back on a circular orbit of the new field; slider changes do not respawn). `respawn()` replaces `state` with a fresh `ShipState` (`rot`, `ang_vel` and fuel counters zero), sets node `position` to `pos` and `rotation` to 0, and spawns on a circular orbit: `pos = (spawn_radius, 0)`, `vel = body_vel(ref) + tangent·circular_speed(ref, pos, t)` with `ref = dominant(pos, t)` and `tangent` counter-clockwise around it (dominant body's pull and distance only; same `v_target` as brake), so the orbit stays circular when the field is retuned. `_read_input` sets `inp.brake` from `ship_brake`. `_physics_process` builds a `ShipInput` and stores it in `var input`, sets `state = ShipFlight.step(state, input, GravityField.time(), GravityField.DT)` (fixed step, so flight stays tick-consistent at any `Engine.time_scale`), calls `move_and_collide(state.pos - position)` ignoring the result, and sets `rotation = state.rot`. `t` is `time()` read after the `GravityField` tick increment (autoloads process before `Run`), the same time `Body` uses, so prediction from tick T uses `t = (T+i+1)/60` for step i. Accepted cost: with no colliders `state.pos` is the node position; once something collides they diverge and need syncing.
- `ShipPrediction.run(state, input, tick, steps) -> PackedVector2Array` (`class_name`, static, pure) repeats `ShipFlight.step` with `t = GravityField.time_at(tick + i + 1)` and `GravityField.DT`, returning the position after each step; it starts from `ship.state` (not node `position`) and is bit-identical to real flight with the same input.
- `Prediction` is a `Line2D` in `Run.tscn` after `Ship` (so it reads the already-stepped state) with `Prediction.gd` and a Ship reference; constant world-space width, not a child of Ship (it must not rotate). Every `maxi(predict_every, 1)` ticks (0 is safe) it sets `points`: short line from `ship.input` for `predict_short_steps`, or while `ship_full_trajectory` is held the full line from a neutral `ShipInput.new()` (coast) for `predict_full_steps`; on other ticks points stay unchanged. Also recomputed immediately on `Tuning.preset_applied` (after the ship respawn, which connected first). The short line keeps the current input to show where thrust is taking the ship; the full line coasts because held thrust would make it spiral away. Accepted cost: the line passes through bodies (bodies have no radius).
- Input: actions in `project.godot` `[input]`: `ship_rotate_left` (A), `ship_rotate_right` (D), `ship_thrust` (W, right trigger, deadzone 0.5: binary), `ship_boost` (Space, joypad button 0), `ship_brake` (S, left trigger axis 4, deadzone 0.5: binary), `ship_heading_left/right/up/down` (left stick axes 0/1), `ship_full_trajectory` (Shift hold, joypad button 7 = left stick click), `debug_tuning_panel` (F1, toggles the `TuningPanel`; handled in the panel's `_unhandled_input`, flight input stays live while it is open and panel controls take no focus). A stick vector beyond the deadzone sets `has_heading` with `target_heading = stick.angle() + PI/2`; otherwise A/D give `turn`.
- `Body.tscn` is a view: Node2D with `Body.gd` (`@export var index`) and a placeholder visual; `_physics_process` sets `position = GravityField.body_pos(index, GravityField.time())`. Params live in `Tuning.field`, not on the node.
- `Carrier.tscn`, `Field.tscn` are empty `Node2D` roots.

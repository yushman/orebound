# scenes

Game scenes.

- `Run.tscn` (Node2D, main scene) holds an instance of `Ship.tscn`, the `Prediction` `Line2D`, and 3 `Body.tscn` instances: planet (`index` 0) and 2 moons (`index` 1, 2).
- `Ship.tscn` is a `CharacterBody2D` named `Ship` with `Ship.gd`, a `Polygon2D` triangle (nose toward local -Y), a `CollisionShape2D` with a `CircleShape2D` and a child `Camera2D` with `ignore_rotation = true` (north stays up).
- Flight physics is the pure `ShipFlight.step(state, input, t, dt) -> ShipState` (`class_name`, static, no scene dependency, so trajectory prediction can reuse it). It returns a new state, never mutates its arguments, and is deterministic. `ShipParams` are read from `Tuning.ship` on each call, no cache.
- Step order: rotation, thrust, translation, fuel. Rotation: angular acceleration is `turn * turn_accel` (turn in {-1, 0, 1}), or with `has_heading` `clamp(heading_gain * wrapf(target_heading - rot, -PI, PI), ±turn_accel)`; then `ang_vel = (ang_vel + ang_acc·dt)·exp(-spin_damping·dt)` (damping always on), `rot += ang_vel·dt`. Thrust acts along the nose `Vector2.UP.rotated(rot)`. Translation is semi-implicit Euler: `vel += (GravityField.accel(pos, t) + nose·thr)·dt`, then `pos += vel·dt`.
- Boost: `boost` alone gives thrust `thrust_accel·boost_accel_mult` (`thrust` is not required) and only `fuel_boost` grows, by `thr·dt·fuel_per_dv·boost_fuel_mult`; plain `thrust` grows only `fuel_engine` by `thr·dt·fuel_per_dv`; no thrust, no fuel. Fuel is per delta-v, so the boost ratio holds under any acceleration tuning. Fuel only accumulates; there is no tank limit.
- `ShipState` (`pos`, `vel`, `rot`, `ang_vel`, `fuel_engine`, `fuel_boost`) and `ShipInput` (`turn`, `has_heading`, `target_heading`, `thrust`, `boost`) are `RefCounted` with typed fields and `copy()`; fuel counters live in the state, not on the node.
- `Ship.gd` holds the authoritative `state`. `_ready` spawns on a circular orbit: `pos = (spawn_radius, 0)`, `vel` perpendicular to the radius with `|vel| = sqrt(R·|GravityField.accel(pos, time())|)`, so the orbit stays circular when the field is retuned. `_physics_process` builds a `ShipInput` and stores it in `var input`, sets `state = ShipFlight.step(state, input, GravityField.time(), GravityField.DT)` (fixed step, so flight stays tick-consistent at any `Engine.time_scale`), calls `move_and_collide(state.pos - position)` ignoring the result, and sets `rotation = state.rot`. `t` is `time()` read after the `GravityField` tick increment (autoloads process before `Run`), the same time `Body` uses, so prediction from tick T uses `t = (T+i+1)/60` for step i. Accepted cost: with no colliders `state.pos` is the node position; once something collides they diverge and need syncing.
- `ShipPrediction.run(state, input, tick, steps) -> PackedVector2Array` (`class_name`, static, pure) repeats `ShipFlight.step` with `t = GravityField.time_at(tick + i + 1)` and `GravityField.DT`, returning the position after each step; it starts from `ship.state` (not node `position`) and is bit-identical to real flight with the same input.
- `Prediction` is a `Line2D` in `Run.tscn` after `Ship` (so it reads the already-stepped state) with `Prediction.gd` and a Ship reference; constant world-space width, not a child of Ship (it must not rotate). Every `predict_every` ticks it sets `points`: short line from `ship.input` for `predict_short_steps`, or while `ship_full_trajectory` is held the full line from a neutral `ShipInput.new()` (coast) for `predict_full_steps`; on other ticks points stay unchanged. The short line keeps the current input to show where thrust is taking the ship; the full line coasts because held thrust would make it spiral away. Accepted cost: the line passes through bodies (bodies have no radius).
- Input: actions in `project.godot` `[input]`: `ship_rotate_left` (A), `ship_rotate_right` (D), `ship_thrust` (W, right trigger, deadzone 0.5: binary), `ship_boost` (Space, joypad button 0), `ship_heading_left/right/up/down` (left stick axes 0/1), `ship_full_trajectory` (Shift hold, joypad button 7 = left stick click). A stick vector beyond the deadzone sets `has_heading` with `target_heading = stick.angle() + PI/2`; otherwise A/D give `turn`.
- `Body.tscn` is a view: Node2D with `Body.gd` (`@export var index`) and a placeholder visual; `_physics_process` sets `position = GravityField.body_pos(index, GravityField.time())`. Params live in `Tuning.field`, not on the node.
- `Carrier.tscn`, `Field.tscn` are empty `Node2D` roots.

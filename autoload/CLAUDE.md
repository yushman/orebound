# autoload

Global singletons registered in `project.godot`.

- `GravityField` is the pure field math: `accel`, `potential`, `potential_eff`, `body_pos`, `body_vel`, `frame_accel`, `frame_omega`, `circular_speed`, `dominant` depend only on their arguments and `Tuning.field` (read on each call, no cache, no node state), so any `t` can be queried. Time is `tick` (int, +1 per `_physics_process`); `DT = 1/60` is the one fixed step, `time_at(n) = n / 60.0` (any tick, used by prediction) and `time() = time_at(tick)`.
- All field mechanics live in the frame rotating with the carrier (D35): body positions and velocities are relative to that frame, `ShipFlight.step` adds the frame terms (`frame_accel`), and the honest gravity g(r) is unchanged. The carrier is a fixed point of the frame by construction of `frame_omega`.
- Per body g(r) = k·M / (r^p + ε), p per body; ε is only in g; Φ is the antiderivative at ε = 0, so −∇Φ ≈ accel only away from body cores. Moon pull (`influence_radius` R > 0) fades by smoothstep to 0 over [R, R·(1+`fade_width`)]; Φ in the fade zone is a numeric integral.
- `body_pos(i, t)` is a circular orbit at the angular speed relative to the frame (`angular_speed − frame_omega()`); `body_vel` is its analytic derivative (parent's velocity added), zero for the planet. `parent = -1` is the origin.
- `accel_of(i, pos, t)` is the fade-weighted pull of body i; `accel` is the sum. `dominant` is the body with the largest `|accel_of|`. `circular_speed(i, pos, t)` is `sqrt(r_i·|accel_of|)` with only body i's pull (0 at its center); the drift-sync fallback uses it.
- `frame_omega()` is derived from the planet pull (`bodies[0]`, fade included, moons ignored) at `carrier_orbit_radius`, recomputed on each call (no cache) so g_eff(r_c) = 0 for any p and any slider. The planet pull is computed from the g(r) formula directly, not through `accel_of` (which calls `body_pos`, which calls `frame_omega`: infinite recursion); a test pins the equality. The carrier is not a body and not a gravity source.
- `planet_potential_eff(r)` is the radial Φ_eff of the planet alone: planet `_phi_body` minus ½·`frame_omega()`²·r², no `t`, no moons, reads `Tuning.field` per call. Strictly increasing on [`atmosphere_edge`, `carrier_orbit_radius`]; the generator root-finds on it.
- `frame_accel(pos, vel)` is centrifugal plus Coriolis; the only place of this math. `potential_eff` is `potential` minus the centrifugal term and is the single effective potential (tiers, isolines, return margin); `potential` stays pure gravity.
- `Tuning.field` is a `FieldParams` Resource (`k`, `eps`, `fade_width`, `planet_surface_radius`, `atmosphere_edge`, `carrier_orbit_radius`, `bodies: Array[BodyParams]`); `BodyParams` has `mass`, `p`, `influence_radius` (0 = unlimited), `parent`, `orbit_radius`, `angular_speed`, `phase`. The code default (script defaults and `Tuning._default_field()`) is the D35 scale: surface 100 000 < atmosphere edge 101 500 < carrier orbit 121 500, a single planet. `Tuning._ready` loads nothing: a fresh start runs on the code defaults and presets are applied only from the panel. A multi-body preset applied on the single-body default is fine: `Tuning.apply` accepts any body count.
- `Tuning.planet` is a `PlanetParams` Resource (`class_name`, `@export`), built in code by `Tuning._default_planet()`, the same for every preset (not in `TuningPreset`, untouched by `apply` / `save_preset` / `load_preset`); read per call, never cached. Holds `tier_shares` (top to bottom `[0.25, 0.40, 0.25, 0.10]`), `ceiling_offset` (5000, ceiling = carrier orbit + offset), moon data for W4 (`moon_count_min/max`, `moon_large_radius_min/max` 1000..2000 on high orbits, `moon_small_radius_min/max` 300..700 on low orbits), ring placeholder data for W5 (`ring_tier`, `ring_width`, `ring_density`, invented numbers) and the atmosphere (`atmosphere_drag` 0.5 1/s at ρ = 1, `atmosphere_damage` 5.0 hull/s at ρ = 1, `density_shape` 2.0 exponent; playtest hypotheses). Radii stay in `FieldParams`.
- `Tuning.ship` is a `ShipParams` Resource (`class_name`, `@export` fields), default built in code. Groups: flight (`thrust_accel`, `boost_accel_mult`, `turn_accel`, `spin_damping`, `heading_gain`, `fuel_per_dv`, `boost_fuel_mult`); D36 controls (`brake_accel`, `brake_fuel_mult`, thrust ramp `ramp_time` and `ramp_min_fraction`, heat `heat_growth_engine` / `heat_growth_boost` / `heat_threshold` / `heat_cooldown` / `min_thrust_fraction`, drift sync `sync_accel` / `sync_fuel_mult` / `sync_radius`); hull (`hull_max` 100.0); prediction (`predict_short_steps`, `predict_every`). D36 values are playtest hypotheses. There is no `predict_full_steps` (`ShipPrediction.run` takes any N) and no `spawn_radius` (the ship spawns at the carrier). Every parameter except preset-level constants is a `TuningPanel` slider (`ui/CLAUDE.md`).
- `TuningPreset` (`class_name`, Resource: `name`, `field`, `ship`) is one `.tres` per preset in `res://presets/` (`p1`..`p4`, `name` «P1 Ньютон», «P2 Плоский 2D», «P3 Компромисс», «P4 Смешанный»), all rescaled to D35: `k`, `eps`, `fade_width` and the three radii are explicit in each file. Planet p: P1 2, P2 1, P3 1.5, P4 1; the planet is static. Every preset has the same two moons (orbit parameters identical; masses and influence radii are playtest hypotheses): a large one (orbit 118 500, `influence_radius` 2000, phase 0) and a small one (orbit 103 500, `influence_radius` 700, phase π), both p = 2, `parent` 0, on a circular orbit of their preset's planet curve. No force normalization in code.
- Fair comparison (D29/D35) is a property of the planet curve: planet mass is chosen per p so the Φ_eff drop between the carrier orbit and the atmosphere edge is equal across presets (the p = 2 recipe sets the target). Consequently Ω_f and the band drift differ by preset; this is intended and visible in A/B. A test pins the equal drop on planet-only fields.
- The ship sub-resource of each `.tres` carries every `ShipParams` field equal to the code defaults, so loading a preset sets a known ship state.
- `Tuning.apply(preset)` replaces `field` and `ship` with deep copies (slider edits never touch the cached resource; no game code caches `Tuning.field` / `Tuning.ship`) and emits `preset_applied`. `Tuning.load_preset(path) -> TuningPreset` loads uncached; `Tuning.save_preset(path, name) -> Error` saves deep copies of the current state.
- `Telemetry` (`extends Node`) holds `crashes: int` (starts 0), incremented by `Ship` on a crash respawn; a preset change does not reset it. No other logic yet.

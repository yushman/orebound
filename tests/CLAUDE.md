# tests

GUT suite, run headless (command in root `CLAUDE.md`).

- Smoke: instancing `res://scenes/Run.tscn` yields a child `Ship` (scripted, with a `Camera2D` child) and 3 `Body.tscn` children with `index` 0, 1, 2; `application/run/main_scene` is `res://scenes/Run.tscn`.
- Autoloads and stub scenes/UI/shaders are checked to exist and load; `HUD` is checked as an empty Control root.
- `test_gravity_field.gd`: `body_pos` orbit formula, tick clock, default field, −∇Φ ≈ accel by finite difference (p = 2, 1, 1.5, fade zone), moon fade bounds and continuity, determinism, mixed p, `accel` = Σ `accel_of`, `dominant` near a moon vs far, `body_vel` vs finite difference of `body_pos`, `circular_speed`. Tests set a custom `Tuning.field` and restore it.
- `test_body.gd`: `Body` places itself at `GravityField.body_pos(index, time())` on physics process.
- `test_ship_flight.gd`: `ShipFlight.step` with a planet-only `Tuning.field` (restored after): circular orbit keeps its radius (~1% over several orbits), thrust along the nose, determinism and non-mutation of inputs, spin damping and heading convergence, boost accel and fuel ratios, zero fuel without thrust; `reference_body`; brake: held brake from a perturbed velocity converges to circular speed (p = 1 and p = 2), per-step brake accel ≤ `brake_accel` < `thrust_accel`, brake ignores thrust/boost, `fuel_brake` > 0 only with brake (with the multiplier), retrograde stays retrograde.
- `test_ship.gd`: spawn on a circular orbit, `t` passed to `step` is `GravityField.time()` (pinned by setting `tick` and calling `_physics_process` directly), `step` gets the fixed `GravityField.DT` whatever the physics callback argument, `ship.input` is the input passed to `step`, camera `ignore_rotation`, spawn speed is the dominant body's `circular_speed` (own pull only, differs from the full `accel`) with a moon near `spawn_radius`; `preset_applied` respawns on a circular orbit of the new field with a fresh state (rot, ang_vel, fuel zero) and node rotation 0, a direct field change does not move the ship.
- `test_ship_prediction.gd`: `ShipPrediction.run` from tick T equals real flight (`ship._physics_process` with `GravityField.tick += 1` per step) point for point with `assert_eq`, with and without `ship_thrust` or `ship_brake` held (brake on a perturbed orbit; `ship_brake` released in `after_each`), inputs not mutated; the `Prediction` Line2D shows `predict_short_steps` points from `ship.input` and, with `ship_full_trajectory` pressed, `predict_full_steps` points from a neutral input, recomputing only every `predict_every` ticks; `predict_every = 0` still updates the line.
- `test_ship_params.gd`, `test_ship_types.gd`, `test_input_actions.gd`: `Tuning.ship` defaults (incl. `predict_*` 180 / 1800 / 4), `ShipState`/`ShipInput` `copy()`, presence of the input actions in `project.godot` (`ship_full_trajectory` is Shift + joypad button 7; `ship_brake` is S + left trigger axis 4, deadzone 0.5; `debug_tuning_panel` is F1); defaults `brake_accel` 200 / `brake_fuel_mult` 1.25 and `fuel_brake` / `brake` in `copy()`.
- `test_run_scene.gd`: `Run` has a `ReferenceMarker` node placed on the reference body (moon 1 when the ship is next to it) and a `CanvasLayer` with a hidden `TuningPanel`.
- `test_tuning_presets.gd`: preset save (to `user://`) / load round trip equal in every field incl. each `BodyParams`; `Tuning.apply` deep copies, emits `preset_applied`, rejects a body-count mismatch; p and mass values of `p1`..`p4`; a fresh `Tuning` loads P4 in `_ready`. Tests restore `Tuning.field` and `Tuning.ship`.
- `test_tuning_panel.gd`: slider change visible on the next `GravityField.accel` call, sliders cover every parameter and write to the current `Tuning` objects, mass / `predict_every` ranges, no control takes focus, Load of a preset syncs sliders without writing back, Save writes the selected preset into `presets_dir`, only `debug_tuning_panel` toggles visibility (event handled); saves go to `user://`, never `res://presets`.

# ui

Screen-space Control scenes.

- `HUD.tscn` is a scripted Control root with `HUD.gd`, instanced under the `CanvasLayer` in `Run.tscn` next to `TuningPanel`. It paints the vertical well scale in `_draw` (no child nodes), anchored to the right edge of the 1280x800 base viewport; `_process` calls `queue_redraw` every frame, nothing is cached. The root and drawing ignore mouse and focus (`MOUSE_FILTER_IGNORE`, `FOCUS_NONE`) and fill the screen; these and the anchors are set in `HUD.tscn`, not in `_ready`. `_ready` looks the ship up once (null-safe when the HUD is instanced alone, no error).
- The scale's vertical axis is the Φ_eff share from the atmosphere edge: 0 at the edge, 1 at the carrier orbit. Layout constants: `BOTTOM_Y` 700 (share 0), `SCALE_H` 560 (share 1 is `BOTTOM_Y − SCALE_H`), `STRIP_H` 60, `BAR_W` 28, `MARGIN` 60 from the right edge; `share_y(s) = BOTTOM_Y − s × SCALE_H`. Sizes are free pixel constants, tuned in playtest.
- Static helpers (pure, tested): `share(r) = (Φp(r) − Φp(edge)) / (Φp(r_c) − Φp(edge))` with `Φp = GravityField.planet_potential_eff`, `edge = Tuning.field.atmosphere_edge`, `r_c = Tuning.field.carrier_orbit_radius`, read per call (moons are ignored: full `potential_eff` is non-monotonic and would stop matching the segments); `segments()` gives `Vector2(bottom, top)` shares per tier, top tier first, cumulative `Tuning.planet.tier_shares` from the bottom, so each tier boundary sits at its cumulative share without calling `WellGenerator.tiers()` at runtime; `tow_share()` = `tier_shares[2] + tier_shares[3]` (0.35 by default); `share_y`; `marker_y(r)`.
- `marker_y(r)`: for `r ≤ r_c` it is `share_y(max(share(r), 0))`, so below the atmosphere edge the marker is clamped to the bottom line; above the carrier Φ_eff falls back, so the marker moves linearly through the "М" strip of `STRIP_H` pixels above the carrier line by `(r − r_c) / Tuning.planet.ceiling_offset`, clamped to the strip top (the ceiling line) for `r` at or beyond the ceiling.
- Drawing: four tier rects with labels "1".."4" top to bottom; the "М" strip with its label; tier rects are `Palette.HALO` tints, lines are `Palette.HALO` and differ by style, not only colour: atmosphere edge solid `Palette.DANGER` (3 px), tow dashed (2 px, `TOW_COLOR` = `Palette.SAFE`), carrier solid (3 px, `CARRIER_COLOR` = `Palette.SAFE`, as the world draws them), ceiling thin (1 px); the ship marker is a `Palette.SAFE` triangle left of the bar's right side at `marker_y(ship.state.pos.length())`.
- Bottom-centre bars (top to bottom, drawn by `_draw_bars`: `_draw_cells` for tank and hold plus the reserve frame, then `_draw_hull`): tank "топливо" at `TANK_Y` 712, hold "трюм" at `HOLD_Y` 742 with the label "масса N" (`Hold.mass`), hull "корпус" at `HULL_Y` 772. Tank and hold are one cell per slot (`tank_capacity` / `hold_capacity`), each cell filled left to right by its `fill`, in the type colour (`cell_color`: `AsteroidView.color_of` for ice and ores, `Palette.FUEL` for fuel) and a pattern (`cell_pattern`: fuel stripes, ice dots, ore_base solid, ore_middle hatch_h, ore_rare hatch_v, ore_unique cross; colour is never the only carrier); the outline is `Palette.HULL` for a full cell, dim `HULL_SHADE` otherwise and for empty slots. Static helpers (pure, tested): `tank_slots(cells)` puts full cells first and the partial one last (the bar shrinks right to left, matching `Hold.drain`), `bar_cells`, `fill_rect`, `hull_segments(hull, hull_max) = ceil(clamp(hull / hull_max, 0, 1) · 5)` (filled segments vs outlines). The hold keeps stored order.
- Reserve state: static `reserve_state(energy, need, reserve)` is BELOW when `energy < need`, NEAR when `energy ≤ reserve`, else CALM; `reserve_color` maps BELOW / NEAR / CALM to `Palette.DANGER` / `Palette.SAFE` / `Palette.HALO`. A frame of that colour surrounds the whole tank bar. `need = Fuel.climb_energy(|pos|, |vel|, Hold.mass(s))`, `energy = Hold.energy(s)`, `reserve = max(Tuning.resources[&"fuel"].energy, need)` (computed in `_draw`); at the carrier `need` is ~0, so with only the last fuel cell left the frame is yellow (a last-cell warning); accepted cost: it may read as a false alarm at the carrier (playtest).
- Reserve strip: a thin (`RESERVE_H` 3 px) hatched `Palette.DANGER` strip under the tank cells (`TANK_Y + CELL_SIZE + 2`) from the bar's left edge (the cells burned last) to `reserve_x(cells, capacity, reserve, rects)`, pure static and tested: it walks the `tank_slots` order over `bar_cells`, each cell counting `fill · energy` of its type plus the unfilled part and empty slots at a fuel cell's energy, and returns the x where the reserve energy ends (clamped to the bar end). At the current balance the strip is one fuel cell; it grows when the climb gets dearer.
- Debug line (top-left at `DEBUG_POS`, `FONT_SIZE`, `Palette.HALO`, drawn only with a ship and only while `../TuningPanel` is visible, i.e. F1; static `debug_visible(panel)` is false for a null or hidden panel): static `debug_text(s: ShipState, need: float)` = `"энергия %.2f · масса %.1f · трюм used/hold_capacity · бак used/tank_capacity · нужно %.2f"` from `Hold.energy` / `Hold.mass` / `Hold.used_volume` / `need` (the `Fuel.climb_energy` value, computed once per `_draw` and shared with the frame), a calibration readout.
- `ship` is a plain var set once in `_ready` from `../../Ship` (or assigned directly); without a ship the scale is drawn without a marker.
- `TuningPanel.tscn` is a dev-only Control root with `TuningPanel.gd`, instanced under a `CanvasLayer` in `Run.tscn`; hidden by default, `debug_tuning_panel` (F1) toggles it in `_unhandled_input` and marks the event handled.
- Header: an `OptionButton` with the full preset names (same as the `name` in `p1`..`p4.tres`; P4 selected on start), Load and Save. Load applies `Tuning.load_preset(<presets_dir>/pN.tres)` via `Tuning.apply(preset, false)` (no emit) and then `Tuning.regenerate(Telemetry.seed, Telemetry.flight)`, so `preset_applied` fires once (presets are planet-only, the moons are regenerated with the current seed); Save overwrites the selected preset with `Tuning.save_preset` at `<presets_dir>/pN.tres` (`presets_dir` defaults to `res://presets`, a dev tool run from the editor; there is no `user://` save and no save-as). A failed load or save is a `push_error`.
- Seed controls: a second `HBox` row under the header with a `SpinBox` `seed_box` (0..2147483647, integer; a change calls `Tuning.regenerate(value, 1)`, i.e. flight reset to 1) and a `Next seed` button (`next_seed_button`: `Tuning.regenerate(max(_requested_seed, Telemetry.seed) + 1, Telemetry.flight)`: the panel keeps `_requested_seed` (set by the box and Next), so after a fallback the next press advances from the requested seed and after a retry past the used one). `_sync` sets `seed_box` from `Telemetry.seed` without a signal, so the box shows the seed actually used. The seed box's inner `LineEdit` is the one exception to no-focus: it has `FOCUS_CLICK` so a seed can be typed; Enter (`text_submitted`) applies the value and releases focus, returning flight keys to the ship; focus loss also applies the typed value (`SpinBox` default).
- Slider rows (Label + `HSlider` + value Label) are built in code from the `ROWS` descriptor list (target `"field"` | `"ship"` | `"planet"` | `"view"` | body index, property, min, max, step). Covered: field `k`, `eps`, `fade_width` (min 0.01: `_fade` divides by it); per body `p` and `mass`, moon `influence_radius`; ship thrust, boost, brake, fuel (`boost_fuel_mult`, `brake_fuel_mult`, `sync_fuel_mult`, `climb_coefficient`), thrust ramp (`ramp_time`, `ramp_min_fraction`), heat, sync prediction (`predict_every`, `predict_short_steps`), `hull_max` and the hold / mass parameters (`hull_mass` 0.5..100, `hold_capacity` 1..40, `ref_mass` 1..100, `loadout_fuel_cells` 0..20, `tank_capacity` 0..20; int props written as int), the return estimate (`return_margin` 1.0..3.0); planet `atmosphere_drag`, `atmosphere_damage`, `density_shape` (ids `planet.<prop>`, written into `Tuning.planet`); planet `moon_mass_k`, `moon_mass_exp`, `moon_influence_k`, `moon_margin` (each also calls `Tuning.regenerate(Telemetry.seed, Telemetry.flight)` to rebuild the moons with the new value; `REGEN_PROPS`), `moon_bounce`, `moon_impact_damage`, `rest_speed` (0..2; read per call by `ShipFlight`, no regeneration); `ring_width`, `ring_density` (in `REGEN_PROPS`: they regenerate and so rebuild `Tuning.picture` and the `RingView`); the asteroid knobs `band_width`, `chunk_arc`, `chunk_gen_radius`, `asteroids_per_band` (100..500), `drop_start`, `drop_ratio`, `above_factor`, `field_radius`, `ast_radius_min`, `ast_radius_max`, `asteroid_bounce`, `asteroid_impact_damage` (written into `Tuning.planet`, no regeneration: chunks are pure functions of `Tuning`, read per call); view `halo_alpha` (0..1), `ring_count` (1..12, int), `ring_period` (0.2..10), `ring_px` (0.5..5), `ring_alpha` (0..1) (ids `view.<prop>`, written into `Tuning.view`). Not sliders (pinned by a negative test): orbit parameters, the D35 radii and `sync_radius` (preset constants), `turn_accel`, `spin_damping`, `heading_gain`; Ω_f is derived. `sliders` maps ids like `field.k`, `body1.mass`, `ship.thrust_accel` to the slider.
- Ranges fit the D35 scale (mass 1..2e7 with `exp_edit`, `influence_radius` 0..20000, `thrust_accel` / `brake_accel` 0..50, fractions 0..1, `predict_every` min 1, `predict_short_steps` 300..1800); code defaults of `Tuning.ship`, `Tuning.planet` and `Tuning.view` must lie inside them (test).
- Mining rows (plain sliders in `ROWS`, written into the current `Tuning.ship` / `Tuning.planet` on change): `ship.beam_range` 0..1000 (step 10), `ship.beam_rate` 0..5 cells/s (step 0.05), `planet.amount_per_area` 1e-5..1e-3 (step 1e-6), `planet.top_ice_share` 0..1 (step 0.01); defaults 300, 0.5, 1.1e-4, 0.6 lie inside.
- A slider change writes straight into the current `Tuning.field` / `Tuning.ship` / `Tuning.planet` / `Tuning.view` / `Tuning.field.bodies[i]` (looked up on every change, never cached; int properties get `int(v)`), so the next `GravityField.accel` / `ShipFlight.step` / Prediction call sees it. Slider changes do not respawn the ship, except the `HOLD_PROPS` ones and the gravity sliders (`GRAVITY_PROPS`: field `k`, `eps`, `fade_width` and body 0 `mass`, `p`), which call `Tuning.regenerate(Telemetry.seed, Telemetry.flight)` so moon `angular_speed` and tiers follow (the ship respawns).
- Small-object rows (plain sliders in `ROWS`, none regenerates the picture): `planet.small_rate` as four indexed rows (0..3, tiers bottom to top; 0..60 events/min, step 0.1), `small_window` 1..300 s, `small_e_min/max` 0..0.99, `small_radius_min/max` 1..200, `swallow_radius` 1..200, `small_spawn_radius` 100..10000, `small_despawn_radius` 100..20000, `small_max_bodies` 0..64, `small_bounce` 0..1, `v_safe` 0..100, `impact_k` 0..1 and `ship.hit_radius` 0..100; defaults lie inside the ranges.
- Hold parameters (`HOLD_PROPS`: `loadout_fuel_cells`, `hold_capacity`, `tank_capacity`): a slider change writes the value and then calls `ship.respawn()` (ship found lazily at `../../Ship`, null-safe), so the new loadout applies at once. `_sync` is signal-free, so it never respawns.
- On `Tuning.preset_applied` (and in `_ready`) `_sync` sets every slider from the current `Tuning` without emitting `value_changed`, so syncing never writes back; values outside a slider's range are kept as is. Rows of bodies with index >= `Tuning.field.bodies.size()` are hidden and skipped (a picture has the planet plus 2..3 moons; the code default before `Run` regenerates has one body), and come back when the generated picture has that many moons (the default `Run` start has the planet and 2..3 moons).
- Every panel control has `focus_mode = FOCUS_NONE` (mouse only), so flight keys never reach it and flight input stays live while the panel is open (except the seed `LineEdit` while it holds focus). Changing a generation knob slider (`REGEN_PROPS` of `planet`) calls `Tuning.regenerate(Telemetry.seed, Telemetry.flight)`, which emits `preset_applied` and so respawns the ship.
- A readout `Label` at the top of the panel is refreshed in `_process` while the panel is visible: ship hull, `ShipFlight.atmosphere_density` at the ship and `Telemetry.crashes`. The Ship node is found at `../../Ship` (or set via `ship`); without one only the crash count is shown.

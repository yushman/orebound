# ui

Screen-space Control scenes.

- `HUD.tscn` is a scripted Control root with `HUD.gd`, instanced under the `CanvasLayer` in `Run.tscn` next to `TuningPanel`. It paints the vertical well scale in `_draw` (no child nodes), anchored to the right edge of the 1280x800 base viewport; `_process` calls `queue_redraw` every frame, nothing is cached. The root and drawing ignore mouse and focus (`MOUSE_FILTER_IGNORE`, `FOCUS_NONE`).
- The scale's vertical axis is the Φ_eff share from the atmosphere edge: 0 at the edge, 1 at the carrier orbit. Layout constants: `BOTTOM_Y` 700 (share 0), `SCALE_H` 560 (share 1 is `BOTTOM_Y − SCALE_H`), `STRIP_H` 60, `BAR_W` 28, `MARGIN` 60 from the right edge; `share_y(s) = BOTTOM_Y − s × SCALE_H`. Sizes are free pixel constants, tuned in playtest.
- Static helpers (pure, tested): `share(r) = (Φp(r) − Φp(edge)) / (Φp(r_c) − Φp(edge))` with `Φp = GravityField.planet_potential_eff`, `edge = Tuning.field.atmosphere_edge`, `r_c = Tuning.field.carrier_orbit_radius`, read per call (moons are ignored: full `potential_eff` is non-monotonic and would stop matching the segments); `segments()` gives `Vector2(bottom, top)` shares per tier, top tier first, cumulative `Tuning.planet.tier_shares` from the bottom, so each tier boundary sits at its cumulative share without calling `WellGenerator.tiers()` at runtime; `tow_share()` = `tier_shares[2] + tier_shares[3]` (0.35 by default); `share_y`; `marker_y(r)`.
- `marker_y(r)`: for `r ≤ r_c` it is `share_y(max(share(r), 0))`, so below the atmosphere edge the marker is clamped to the bottom line; above the carrier Φ_eff falls back, so the marker moves linearly through the "М" strip of `STRIP_H` pixels above the carrier line by `(r − r_c) / Tuning.planet.ceiling_offset`, clamped to the strip top (the ceiling line) for `r` at or beyond the ceiling.
- Drawing: four tier rects with labels "1".."4" top to bottom; the "М" strip with its label; tier rects are `Palette.HALO` tints, lines are `Palette.HALO` and differ by style, not only colour: atmosphere edge solid `Palette.DANGER` (3 px), tow dashed (2 px), carrier solid (3 px), ceiling thin (1 px); the ship marker is a `Palette.SAFE` triangle left of the bar's right side at `marker_y(ship.state.pos.length())`.
- Hold bar (bottom centre, drawn by `_draw_hold`): the label "трюм" and `CARGO_MAX` 6 cells in a row, `CELL_SIZE` 20, `CELL_GAP` 6, top at `CELL_Y` 750, the label `LABEL_GAP` 12 left of the first cell. Static helpers: `cargo_count(fill)` = `roundi(clamp(fill, 0, 1) · CARGO_MAX)`; `cell_filled(i, fill)` = `i < cargo_count(fill)`; `cargo_cells(width = BASE_W 1280)` gives the cell rects, the row centred on `width`. Filled cells are `CARGO_FILL_COLOR` (`Palette.ORE`) rects, empty ones `CARGO_EMPTY_COLOR` (`Palette.HALO`) 2 px outlines (filled vs outline, not only colour). Fill comes from `Tuning.view.cargo_fill`, a placeholder until the real hold.
- `ship` is a plain var; while null, `_draw` looks it up as `../../Ship` (as `TuningPanel` does) on every redraw; without a ship the scale is drawn without a marker.
- `TuningPanel.tscn` is a dev-only Control root with `TuningPanel.gd`, instanced under a `CanvasLayer` in `Run.tscn`; hidden by default, `debug_tuning_panel` (F1) toggles it in `_unhandled_input` and marks the event handled.
- Header: an `OptionButton` with the full preset names (same as the `name` in `p1`..`p4.tres`; P4 selected on start), Load and Save. Load applies `Tuning.load_preset(<presets_dir>/pN.tres)` via `Tuning.apply` and then `Tuning.regenerate(Telemetry.seed, Telemetry.flight)` (presets are planet-only, the moons are regenerated with the current seed); Save overwrites the selected preset with `Tuning.save_preset` at `<presets_dir>/pN.tres` (`presets_dir` defaults to `res://presets`, a dev tool run from the editor; there is no `user://` save and no save-as). A failed load or save is a `push_error`.
- Seed controls: a second `HBox` row under the header with a `SpinBox` `seed_box` (0..2147483647, integer; a change calls `Tuning.regenerate(value, 1)`, i.e. flight reset to 1) and a `Next seed` button (`next_seed_button`: `Tuning.regenerate(Telemetry.seed + 1, Telemetry.flight)`, based on the seed used, not the requested one). `_sync` sets `seed_box` from `Telemetry.seed` without a signal, so the box shows the seed actually used. The seed box's inner `LineEdit` is the one exception to no-focus: it has `FOCUS_CLICK` so a seed can be typed; Enter (`text_submitted`) applies the value and releases focus, returning flight keys to the ship; focus loss also applies the typed value (`SpinBox` default).
- Slider rows (Label + `HSlider` + value Label) are built in code from the `ROWS` descriptor list (target `"field"` | `"ship"` | `"planet"` | `"view"` | body index, property, min, max, step). Covered: field `k`, `eps`, `fade_width` (min 0.01: `_fade` divides by it); per body `p` and `mass`, moon `influence_radius`; ship thrust, boost, brake, fuel, thrust ramp (`ramp_time`, `ramp_min_fraction`), heat, sync prediction (`predict_every`, `predict_short_steps`) and `hull_max` parameters; planet `atmosphere_drag`, `atmosphere_damage`, `density_shape` (ids `planet.<prop>`, written into `Tuning.planet`); planet `moon_mass_k`, `moon_mass_exp`, `moon_influence_k`, `moon_margin` (each also calls `Tuning.regenerate(Telemetry.seed, Telemetry.flight)` to rebuild the moons with the new value; `REGEN_PROPS`), `moon_bounce`, `moon_impact_damage` (read per call by `ShipFlight`, no regeneration); `ring_width`, `ring_density` (in `REGEN_PROPS`: they regenerate and so rebuild `Tuning.picture` and the `RingView`); the asteroid knobs `band_width`, `chunk_arc`, `chunk_gen_radius`, `asteroids_per_band` (100..500), `drop_start`, `drop_ratio`, `above_factor`, `field_radius`, `ast_radius_min`, `ast_radius_max`, `asteroid_bounce`, `asteroid_impact_damage` (written into `Tuning.planet`, no regeneration: chunks are pure functions of `Tuning`, read per call); view `halo_alpha` (0..1), `ring_count` (1..12, int), `ring_period` (0.2..10), `ring_px` (0.5..5), `ring_alpha` (0..1), `cargo_fill` (0..1, the placeholder cargo fill of the HUD hold bar) (ids `view.<prop>`, written into `Tuning.view`). Not sliders (pinned by a negative test): orbit parameters, the D35 radii and `sync_radius` (preset constants), `turn_accel`, `spin_damping`, `heading_gain`; Ω_f is derived. `sliders` maps ids like `field.k`, `body1.mass`, `ship.thrust_accel` to the slider.
- Ranges fit the D35 scale (mass 1..2e7 with `exp_edit`, `influence_radius` 0..20000, `thrust_accel` / `brake_accel` 0..50, fractions 0..1, `predict_every` min 1, `predict_short_steps` 300..1800); code defaults of `Tuning.ship`, `Tuning.planet` and `Tuning.view` must lie inside them (test).
- A slider change writes straight into the current `Tuning.field` / `Tuning.ship` / `Tuning.planet` / `Tuning.view` / `Tuning.field.bodies[i]` (looked up on every change, never cached; int properties get `int(v)`), so the next `GravityField.accel` / `ShipFlight.step` / Prediction call sees it. Slider changes do not respawn the ship.
- On `Tuning.preset_applied` (and in `_ready`) `_sync` sets every slider from the current `Tuning` without emitting `value_changed`, so syncing never writes back; values outside a slider's range are kept as is. Rows of bodies with index >= `Tuning.field.bodies.size()` are hidden and skipped (a picture has the planet plus 2..3 moons; the code default before `Run` regenerates has one body), and come back when the generated picture has that many moons (the default `Run` start has the planet and 2..3 moons).
- Every panel control has `focus_mode = FOCUS_NONE` (mouse only), so flight keys never reach it and flight input stays live while the panel is open (except the seed `LineEdit` while it holds focus). Changing a generation knob slider (`REGEN_PROPS` of `planet`) calls `Tuning.regenerate(Telemetry.seed, Telemetry.flight)`, which emits `preset_applied` and so respawns the ship.
- A readout `Label` at the top of the panel is refreshed in `_process` while the panel is visible: ship hull, `ShipFlight.atmosphere_density` at the ship and `Telemetry.crashes`. The Ship node is found at `../../Ship` (or set via `ship`); without one only the crash count is shown.
